The `attachments` command (aliases `attachment`, `a`) surfaces Redmine's [Attachments API](https://www.redmine.org/projects/redmine/wiki/Rest_api#Attachments) so you can inspect an attachment's metadata and download its bytes. Downloads reuse the active profile's server and API key, streaming straight to disk - no `curl`, no manually extracted key.

## get

```bash
redmine attachments get <id> [flags]
```

Aliases: `show`, `view`, `metadata`. Fetches the attachment's ID, filename, size, content type, description, author, and creation time via `GET /attachments/:id.json`. Table output also shows the download URL (when present); `json` returns every field, including `content_url`.

| Flag | Description |
|------|-------------|
| `-o, --output` | Output format: `table`, `json` |

    ```bash
    redmine attachments get 42
    ```
  </TabItem>
  <TabItem label="JSON">
    ```bash
    redmine attachments get 42 -o json
    ```
  </TabItem>
</Tabs>

## download

```bash
redmine attachments download <id> [flags]
```

Aliases: `dl`, `get-file`. Streams the attachment's raw bytes to disk (or stdout), authenticating with the active profile. The response is streamed, never buffered entirely in memory, so large files are safe.

| Flag | Description |
|------|-------------|
| `-d, --dir`    | Directory to save into, using the attachment's real filename (created if missing) |
| `--path`       | Exact destination file path. Use `-` to stream to stdout |
| `--clobber`    | Overwrite an existing file at the destination |
| `--allow-hidden` | Allow saving under a server-supplied filename that starts with `.` (with `--dir` or the default destination) |
| `-o, --output` | Confirmation format: `json` prints a result object; otherwise a human line is written to stderr |

With no destination flag, the file is saved as `./<filename>` in the current directory.

### Existing files and `--clobber`

Downloads never overwrite an existing file unless you pass `--clobber`. This applies to `--path`, `--dir`, and the default current directory. Without it, the command fails before downloading and names the path:

```text
failed to download attachment 42: logo.png already exists; use --clobber to overwrite it
```

The bytes are first streamed into a temporary file in the destination directory and moved into place only once the download has completed. As a result:

- A failed or interrupted download leaves any existing file untouched and leaves no partial file at the destination. Pressing Ctrl-C once stops the download and removes its temporary file. If the process is killed outright (a second Ctrl-C, `kill -9`), a hidden `.redmine-download-*.tmp` file may remain in the destination directory; it is safe to delete.
- A symlink at the destination is never followed. Without `--clobber` it counts as an existing file (even when it is dangling); with `--clobber` the link itself is replaced by the downloaded file, and whatever it pointed to is left alone.
- A directory at the destination is always an error, even with `--clobber`. So is any other non-regular file, except that a `--path` that is (or links to) a character device or a named pipe, such as `/dev/null` or a FIFO, is written into directly, without `--clobber`. (`/dev/stdout` counts when stdout is a terminal or a pipe; to write to stdout, prefer `--path -`.) With `--dir` or the default destination such an entry is refused like a directory.
- A new file gets the same permissions as any other file you create (`0644` with the usual umask `022`). With `--clobber`, a replaced regular file keeps its previous permissions.

Without `--clobber`, the final step uses a hard link, which fails atomically if a file appeared at the destination while the download was running. On filesystems without hard-link support the CLI falls back to re-checking the destination and then renaming, which leaves a small window between the check and the rename.

<Aside type="caution" title="Changed behavior">
  Earlier versions silently truncated an existing file at the destination and
  wrote through symlinks. Scripts that re-download into the same location now
  need `--clobber`.
</Aside>

With `--dir` or the default destination the filename comes from the server. It is reduced to its base name, so it can never escape the directory. A name that starts with `.` (such as `.bashrc`, `.envrc` or `.npmrc`) is refused, because it could plant or shadow a configuration file, unless you pass `--allow-hidden`:

```text
failed to download attachment 42: refusing to save the hidden filename ".bashrc" as downloads/.bashrc; pass --allow-hidden to save it anyway
```

Choosing the name yourself with `--path` is not affected, and neither is `--path -` (stdout).

If the server redirects the download (or any other request), the redirect is followed only when it stays on the configured server (the same host and port, or the `https://` upgrade of an `http://` server, port 80 becoming 443), or goes to a public address (for example presigned object-storage URLs such as S3). Credentials are only sent to the configured server, never to the redirect target. Redirects from `https://` to `http://`, or to loopback, private, link-local, multicast, unspecified (`0.0.0.0/8`), carrier-grade NAT (`100.64.0.0/10`), or benchmarking (`198.18.0.0/15`) addresses are refused, including IPv6 addresses that embed one of them (IPv4-mapped, NAT64 `64:ff9b::/96`, 6to4 `2002::/16`); host names are re-checked against the address actually connected to. When the redirect goes through an HTTP(S) proxy, the CLI never connects to the target itself, so it resolves the host name locally and refuses it if it points at one of these addresses; a name only the proxy can resolve is left to the proxy. Another port on the configured server's host gets the same checks as any other host. A redirect to a public `http://` URL is followed as long as it does not come from an `https://` URL.

<Aside>
  Unlike most commands, `-o/--output` here controls only the **confirmation**
  output, not where the bytes go - use `--dir` / `--path` for that. When
  streaming to stdout (`--path -`), the bytes go to stdout and the confirmation
  always goes to stderr, so the pipe stays clean even with `-o json`.
</Aside>

## update

```bash
redmine attachments update <id> [flags]
```

Aliases: `edit`. Changes an attachment's metadata via `PUT /attachments/:id.json`. At least one flag is required; only the flags you pass are changed.

| Flag | Description |
|------|-------------|
| `--filename`     | New filename |
| `--description`  | New description; an empty value (`--description ""`) clears it |
| `--content-type` | New content type, for example `image/png` |

```bash
redmine attachments update 42 --filename report-final.pdf
redmine attachments update 42 --description "Final version"
```

You need permission to edit the object the attachment belongs to (for an issue attachment, the right to edit that issue).

## delete

```bash
redmine attachments delete <id> [flags]
```

Aliases: `rm`. Permanently deletes the attachment. Asks for confirmation unless `--force` is given; declining prints `Delete cancelled` and changes nothing. Deleting an issue attachment is recorded in the issue history.

| Flag | Description |
|------|-------------|
| `-f, --force` | Skip the confirmation prompt |

```bash
redmine attachments delete 42
redmine attachments delete 42 --force
```

## thumbnail

```bash
redmine attachments thumbnail <id> --path <file> [flags]
```

Aliases: `thumb`. Downloads the thumbnail Redmine renders for an image attachment (and PDFs where the server supports it).

| Flag | Description |
|------|-------------|
| `--path`       | Destination file path (required). Use `-` to stream the image to stdout |
| `--size`       | Edge length in pixels. Redmine rounds it up to a multiple of 50 and caps it at 800; omitted = the server's default thumbnail size |
| `--clobber`    | Overwrite an existing file at the destination |
| `-o, --output` | Confirmation format: `json` prints `{id, path, bytes, size}`; otherwise a human line is written to stderr |

An existing file is never overwritten without `--clobber`, and a failed request leaves no file behind (same safe-write behavior as [`download`](#existing-files-and---clobber)). With `--path -` the bytes go to stdout, the confirmation to stderr, and `--jq` is rejected.

```bash
redmine attachments thumbnail 42 --path thumb.png
redmine attachments thumbnail 42 --size 200 --path thumb.png --clobber
redmine attachments thumbnail 42 --path - > thumb.png
```

<Aside type="note">
  Redmine answers `404 Not Found` when the attachment cannot be thumbnailed: it is not an image or PDF, or the server has no ImageMagick (`convert`) installed. The CLI reports this as `not_found`.
</Aside>
