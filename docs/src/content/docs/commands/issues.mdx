## list

```bash
redmine issues list [flags]
```

| Flag | Description |
|------|-------------|
| `--project`              | Filter by project (name, identifier, or ID) |
| `--tracker`              | Filter by tracker (name or ID) |
| `--status`               | Filter by status: `open`, `closed`, `*`, name, or ID |
| `--assignee`             | Filter by assignee: `me`, name, login, or ID |
| `--author`               | Filter by author: `me`, name, login, or ID |
| `--priority`             | Filter by priority (name or ID) |
| `--category`             | Filter by issue category (name or ID) |
| `--version`              | Filter by target version (name or ID) |
| `--parent`               | Restrict to children of a parent issue ID |
| `--subproject`           | Subproject filter: numeric ID, or `!*` to exclude subprojects |
| `--include-subprojects`  | Include issues from subprojects (default `true`; pair with `=false` to exclude) |
| `--is-private`           | Filter by privacy: `true` returns private issues only, `false` public only |
| `--filter`               | Raw Redmine filter as `key=value` (repeatable). Use for date ranges, custom fields, subject text |
| `--query`                | Run a saved query by name (see [`queries`](/commands/queries/)) |
| `--query-id`             | Run a saved query by numeric ID (mutually exclusive with `--query`) |
| `--sort`                 | Sort order, e.g. `updated_on:desc` |
| `--include`              | Include related data: `attachments`, `relations` |
| `--attachments`          | Shorthand for `--include attachments` |
| `--relations`            | Shorthand for `--include relations` |
| `--limit`                | Maximum number of results (0 for all) |
| `--offset`               | Result offset for pagination |
| `-o, --output`           | Output format: `table`, `json`, `csv` |

<Aside type="tip">
  `--filter` is an escape hatch for Redmine's filter operator syntax. Examples:

  - `--filter created_on='>=2025-01-01'` — created on or after a date
  - `--filter updated_on='><2025-01-01|2025-12-31'` — updated in a range
  - `--filter cf_5='Critical'` — custom field `cf_5` equals "Critical"
  - `--filter subject='~login'` — subject contains "login"
</Aside>

<Tabs syncKey="issues-list">
  <TabItem label="Mine">
    ```bash
    redmine issues list --assignee me
    ```
  </TabItem>
  <TabItem label="Project bugs">
    ```bash
    redmine issues list --project myproject --tracker Bug
    ```
  </TabItem>
  <TabItem label="Recently closed">
    ```bash
    redmine issues list --status closed --sort updated_on:desc
    ```

## get

```bash
redmine issues get <id> [flags]
```

Aliases: `show`, `view`.

| Flag | Description |
|------|-------------|
| `--include`                | Include related data: `journals`, `children`, `relations`, `attachments` |
| `--journals`               | Shorthand for `--include journals` |
| `--children`               | Shorthand for `--include children` |
| `--relations`              | Shorthand for `--include relations` |
| `--attachments`            | List the issue's attachments (id, filename, size, content type) |
| `--download-attachments`   | Download every attachment of the issue into the given directory |
| `-o, --output`             | Output format |

<Tabs syncKey="issues-get">
  <TabItem label="Attachments">
    ```bash
    # List attachment IDs so you can download one
    redmine issues get 123 --attachments
    ```
  </TabItem>
  <TabItem label="Download all">
    ```bash
    # Pull every attachment into ./issue-123
    redmine issues get 123 --download-attachments ./issue-123
    ```
  </TabItem>
</Tabs>

<Aside type="tip">
  `--attachments` surfaces each attachment's ID. Feed that ID to
  [`attachments download <id>`](/commands/attachments/#download) to fetch a single
  file, or use `--download-attachments <dir>` to grab them all at once.
</Aside>

## create

```bash
redmine issues create [flags]
```

| Flag | Description |
|------|-------------|
| `--project`         | Project (name, identifier, or ID) — falls back to the default project of the active profile |
| `--subject`         | Issue subject — <Badge text="required" variant="danger" /> |
| `--tracker`         | Tracker (name or ID) |
| `--status`          | Status (name or ID) |
| `--priority`        | Priority (name or ID) |
| `--assignee`        | Assignee: `me`, name, or ID |
| `--description`     | Issue description |
| `--description-file` | Read the description from a file (`-` reads standard input); mutually exclusive with `--description` |
| `--parent`          | Parent issue ID |
| `--category`        | Category (name or ID) |
| `--version`         | Target version (name or ID) |
| `--start-date`      | Start date (`YYYY-MM-DD`) |
| `--due-date`        | Due date (`YYYY-MM-DD`) |
| `--estimated-hours` | Estimated hours |
| `--private`         | Mark as private |
| `--watcher`         | Initial watcher (name, login, ID, or `me`; repeatable) |
| `--custom-field`    | Custom field value as `name=value` or `id=value` (repeatable) |
| `--attach`          | File path to attach (repeatable) |

```bash
redmine issues create --project myproject --subject "Add search" --tracker Feature --priority High

redmine issues create --project myproject --subject "Bug report" \
  --start-date 2026-05-01 --due-date 2026-05-15 \
  --watcher me --watcher "QA Bot" \
  --custom-field Severity=High \
  --attach /path/to/screenshot.png --attach /path/to/log.txt

# Values with spaces: quote the whole pair and repeat the flag per field
redmine issues create --project myproject --subject "Bug" \
  --custom-field "2=Value for field 2" \
  --custom-field "61=Value for 61"

# Long Textile/Markdown description from a file, no shell quoting needed
redmine issues create --project myproject --subject "Spec" --description-file spec.textile
```

If Redmine starts the new issue in a different status than `--status` asked for (its workflow does not allow new issues of that tracker to start there for your role), the command prints a warning on stderr. It still exits `0`, because the issue was created and a retry would duplicate it.

## update

```bash
redmine issues update <id> [flags]
```

Accepts the same flags as `create` (except `--project` and `--watcher`) plus:

| Flag | Description |
|------|-------------|
| `--note`           | Add a journal note |
| `--note-file`      | Read the journal note from a file (`-` reads standard input); mutually exclusive with `--note` |
| `--description-file` | Read the new description from a file (`-` reads standard input); mutually exclusive with `--description` |
| `--private-notes`  | Mark the journal note from `--note` / `--note-file` as private |
| `--done-ratio`     | Completion percentage (0-100) |
| `--start-date`     | Start date (empty string clears) |
| `--due-date`       | Due date (empty string clears) |
| `--custom-field`   | Custom field value as `name=value` or `id=value` (repeatable) |
| `--attach`         | File path to attach (repeatable) |

```bash
redmine issues update 123 --note "Fixed the bug" --attach /path/to/fixed_code.patch

# Private journal note visible only to staff
redmine issues update 123 --note "Internal context" --private-notes

# Update custom field by name
redmine issues update 123 --custom-field Severity=Critical

# Long description from a file, note piped in on stdin
redmine issues update 123 --description-file description.textile
generate-report | redmine issues update 123 --note-file -
```

### Status changes are verified

Redmine answers an issue update with success even when it **silently ignores** the requested status: transitions its workflow does not allow for your role and the issue's tracker are dropped, and so is closing an issue that still has open subtasks or is blocked by an open issue. So whenever a status change is requested (`update --status`, `close`, `reopen`), the CLI reads the issue back. If the status did not change:

- a warning explaining why is printed on stderr, including the statuses you *can* move the issue to (Redmine 5.0+; older servers say they cannot report them),
- `-o json` prints the usual action envelope with `"ok": false` and the explanation in `message`,
- the command exits with status `1`.

Other changes sent in the same request (fields, notes, attachments) may still have been applied, so do not resend them blindly. Updates without a status change do not trigger the extra request.

```bash
$ redmine issues close 123 -o json
WARNING: Issue #123: status was not changed to "Closed" (ID 5); it is still "New" (ID 1). Redmine silently ignores status transitions that its workflow does not allow for your role and the issue's tracker, and refuses to close issues that have open subtasks or are blocked by open issues. Allowed statuses: New (1), In Progress (2), Resolved (3), Feedback (4).
{
  "ok": false,
  "action": "closed",
  "resource": "issue",
  "id": 123,
  "message": "Issue #123: status was not changed to \"Closed\" (ID 5); ..."
}
$ echo $?
1
```

The action envelope is unchanged otherwise; to see the issue after an update, run `redmine issues get <id>`.

## assign

```bash
redmine issues assign <id> <user-id-or-name> [flags]
```

The user argument accepts a numeric ID, login, full name, or `me`.

## comment

```bash
redmine issues comment <id> --message "Your comment" [flags]
```

| Flag | Description |
|------|-------------|
| `-m, --message`      | Comment text |
| `-F, --message-file` | Read the comment from a file (`-` reads standard input); mutually exclusive with `--message` |

```bash
redmine issues comment 123 --message-file notes.textile
git log -1 --format=%B | redmine issues comment 123 -F -
```

File contents are sent exactly as read (UTF-8, no trimming), so multi-line Textile or Markdown needs no shell quoting.

## watchers

```bash
redmine issues watchers list <id>
redmine issues watchers add <id> <user>
redmine issues watchers remove <id> <user>
```

`<user>` accepts a numeric ID, login, full name, or `me`.

```bash
redmine issues watchers add 123 me
redmine issues watchers list 123
redmine issues watchers remove 123 alice
```

## relations

```bash
redmine issues relations list <id>
redmine issues relations add <id> --to <other-id> --type <type> [--delay <days>]
redmine issues relations remove <relation-id>
```

| Flag | Description |
|------|-------------|
| `--to`    | Target issue ID — <Badge text="required" variant="danger" /> |
| `--type`  | Relation type. Default `relates`. See table below |
| `--delay` | Number of days delay. Only valid for `precedes`/`follows` |

Supported relation types (from the [Redmine REST docs](https://www.redmine.org/projects/redmine/wiki/Rest_IssueRelations)):

| Type | Meaning |
|------|---------|
| `relates`     | Generic association |
| `duplicates`  | This issue duplicates the target |
| `duplicated`  | This issue is duplicated by the target |
| `blocks`      | This issue blocks the target |
| `blocked`     | This issue is blocked by the target |
| `precedes`    | This issue precedes the target (accepts `--delay`) |
| `follows`     | This issue follows the target (accepts `--delay`) |
| `copied_to`   | This issue was copied to the target |
| `copied_from` | This issue was copied from the target |

```bash
redmine issues relations add 123 --to 124 --type blocks
redmine issues relations add 123 --to 124 --type precedes --delay 5
redmine issues relations list 123
redmine issues relations remove 42
```

<Aside type="note">
  `relations remove` takes the **relation ID**, not an issue ID. Use `relations list` first to discover the relation IDs on an issue.
</Aside>

## delete

<Badge text="destructive" variant="caution" />
```bash
redmine issues delete <id> [flags]
```

| Flag | Description |
|------|-------------|
| `-f, --force` | Skip confirmation prompt |

<Aside type="caution">
  Delete is permanent and cannot be undone via the CLI. Prefer `close` unless you are certain.
</Aside>

## open

```bash
redmine issues open <id>
```

Constructs the issue URL from your configured Redmine server and opens it in your default browser.

```bash
redmine issues open 123   # → https://redmine.example.com/issues/123
```

## browse

```bash
redmine issues browse [flags]
```

Opens an interactive terminal browser for issues. Accepts the same filter flags as [`list`](#list).
