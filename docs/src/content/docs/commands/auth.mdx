## login

Start an interactive login wizard:

```bash
redmine auth login
redmine auth login --name work   # explicit profile name
redmine auth login --header "User-Agent: Mozilla/5.0"   # server behind a picky firewall
```

| Flag | Description |
|------|-------------|
| `--name` | Profile name (default: derived from server hostname) |
| `--keyring` | Store credentials in the system keyring instead of the plaintext config file. See [Configuration](/getting-started/configuration/#system-keyring-optional). |
| `--header` | Global flag. Headers are used for the connection test and saved to the profile. See [Custom HTTP headers](/getting-started/configuration/#custom-http-headers). |

The API key and password prompts are masked. If the server URL uses `http://` and the host is not loopback, the wizard points out once, before asking for credentials, that they will be sent unencrypted; plain `http://` is still accepted (see [Connection security](/getting-started/configuration/#connection-security)).

Logging in again keeps the profile's `read_only` and `mcp` settings.

### Non-interactive login

Without a terminal (CI, scripts, AI agents) the wizard cannot run. Pass the global `--server` together with `--api-key-file` (`-` reads standard input) or `--api-key`, and no prompt is shown: the URL is normalized, the connection is tested, and the profile is saved and activated.

```bash
echo "$REDMINE_KEY" | redmine auth login --server https://redmine.example.com --api-key-file -
redmine auth login --server redmine.example.com --api-key-file ~/.redmine-key --name work --default-project web -o json
```

`-o json` prints the usual action envelope (`"action": "logged_in"`). With missing values and no terminal the command fails immediately and names the flags to pass. In a terminal, values given as flags are not asked for again.

| Flag | Description |
|------|-------------|
| `--server`, `-s` | Global flag. Server URL; skips the URL prompt. |
| `--api-key-file`, `--api-key` | Global flags. API key; skip the credential prompt. Prefer `--api-key-file` so the key stays out of the process list. |
| `--default-project` | Project identifier saved as the profile's default (checked against the server). |

### Server URL normalization

The URL is cleaned up before it is saved, and the wizard tells you when it changed it: surrounding whitespace, query, fragment and trailing slashes are dropped, `https://` is added when no scheme is given (an explicit `http://` is kept), and a Redmine page copied from the browser is reduced to the base URL (`https://host/projects/foo/issues` becomes `https://host`). A sub-path installation is preserved: `https://host/redmine/issues/5` becomes `https://host/redmine`. Server values from `REDMINE_SERVER` or a profile only get `https://` added when the scheme is missing.

<Aside type="tip">
  Run `redmine auth login` again at any time to add another profile — the wizard never overwrites an existing one without confirmation.
</Aside>

## list

```bash
redmine auth list
```

Shows each profile's server URL and which one is currently active.

## switch

```bash
redmine auth switch
```

Opens an interactive selector. The picked profile becomes the default for subsequent commands.

## status

```bash
redmine auth status
```

Displays the active profile name, server URL, authentication method, and the user the credentials resolve to.

When the check fails, the output says why instead of a bare failure:

| `reason` | Meaning |
|----------|---------|
| `credentials_rejected` | Redmine answered 401: the API key (or, for basic auth, the username and password) is invalid, revoked or missing, or the account is locked. With basic auth, an account with two-factor authentication also gets 401 and must use an API key. Redmine then treats requests as anonymous, so commands on publicly readable instances may still return public data. |
| `rest_api_disabled` | Redmine answered 403 on `/users/current.json`, which every logged-in user may read. The REST API is probably disabled (an administrator must enable Administration > Settings > API > Enable REST web service), or a proxy or firewall blocks the request. |
| `request_failed` | The request did not complete (network error, timeout, server error), so the credentials could not be verified. |

With `-o json`, `active` is `false` and the payload adds `reason`, `message` and `hint`; `anonymous: true` is added for the first two reasons. These fields are absent when the check succeeds.

## logout

<Badge text="destructive" variant="caution" />
```bash
redmine auth logout              # current profile
redmine auth logout work         # named profile
```

You will be prompted to confirm before removal.

<Aside type="caution" title="API keys in backups">
  After logout, revoke the corresponding API key in Redmine if it may exist in shell history or backups.
</Aside>
