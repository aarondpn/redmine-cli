The `my-account` command backs the Redmine `/my/account.json` endpoint. It is the only user-write path Redmine exposes to non-admin users — anyone who can authenticate can update their own first name, last name, email, language, notification settings and preferences without admin help.

  <LinkCard title="get"    href="#get"    description="Show your own account details, including api_key and custom fields." />
  <LinkCard title="update" href="#update" description="Update your own name, email, language, notifications, or preferences." />
</CardGrid>

<Aside type="note" title="How this differs from users me">
  `users me` returns the user record from `/users/current.json` — the same view another admin would see. `my-account get` returns `/my/account.json`, which additionally includes your **API key** and any **custom fields** on your profile, and is paired with the writable `my-account update`.
</Aside>

## get

```bash
redmine my-account get [flags]
```

Aliases: `show`, `view`. Shows ID, login, name, email, admin flag, status, mail notification preference, API key (when populated), custom fields, created/last-login timestamps. Redmine never sends `status` on `/my/account.json`, so the Status row shows `unknown` and the key is absent from JSON output.

| Flag | Description |
|------|-------------|
| `-o, --output` | Output format |

## update

```bash
redmine my-account update [flags]
```

Alias: `edit`. Updates your own account. Only flags you explicitly set are sent to the server — partial updates do not clobber other fields.

| Flag | Description |
|------|-------------|
| `--firstname`         | New first name |
| `--lastname`          | New last name |
| `--mail`              | New email address |
| `--language`          | Interface language code such as `en`, `de` or `pt-BR`; empty for the server default. Write-only: no API response returns it |
| `--mail-notification` | Email notification preference: `all`, `selected`, `only_my_events`, `only_assigned`, `only_owner`, `only_my_watches` (Redmine 7.0+), `none`. `selected` notifies about the `--notified-project` set |
| `--notified-project`  | Project (identifier, name, or ID) to get all notifications for with `--mail-notification selected` (repeatable). Only projects you are a member of count. Replaces the current set; `""` clears it. Write-only: no API response returns it |
| `--pref`              | Preference as `key=value` (repeatable), for example `no_self_notified=1`, `hide_mail=1`, `time_zone=Berlin`, `comments_sorting=desc`. Write-only: no API response returns it. See [user preferences](/commands/users/#preferences) for the keys |
| `--custom-field` | Custom field value as `name=value` or `id=value` (repeatable; repeat a field for multi-value fields, `name=` clears it). See [custom field values](/commands/issues/#custom-field-values) |

```bash
# Notifications only for two projects, and none about your own changes
redmine my-account update --mail-notification selected --notified-project web --notified-project api --pref no_self_notified=1

# Interface language and time zone
redmine my-account update --language de --pref time_zone=Berlin
```

`no_self_notified` is a preference, not a user attribute, so it goes through `--pref`.

<Aside type="note" title="Custom fields">
  Redmine only applies the custom fields the administrator made editable for users. Looking fields up by name needs admin rights; otherwise get the numeric IDs with `redmine my-account get --jq '.custom_fields'`.
</Aside>

<Aside type="caution" title="Works without admin">
  Unlike `users update`, `my-account update` does **not** require admin privileges — every authenticated user can change their own profile. Be sure the API key you're using really belongs to the account you intend to modify.
</Aside>
