The `users` command (alias `u`) manages Redmine users. All write operations require admin privileges; non-admin self-service lives under [`my-account`](./my_account/).

## list

```bash
redmine users list [flags]
```

| Flag | Description |
|------|-------------|
| `--status`     | Filter by status: `active`, `registered`, `locked`, `all`, or a numeric status. Default: Redmine lists active users only |
| `--name`       | Filter by name or login |
| `--group`      | Filter by group name or ID |
| `--sort`       | Sort order, e.g. `lastname` or `created_on:desc` |
| `--filter`     | Raw Redmine filter as `key=value` (repeatable). The generic `f[]`/`op[]`/`v[]` filters need Redmine 5.1+ |
| `--include`    | Include related data: `auth_source` (Redmine 6.0+, admin only; repeatable or comma-separated) |
| `--limit`      | Maximum number of results |
| `--offset`     | Result offset for pagination |
| `-o, --output` | Output format |

<Aside type="note" title="Listing every status">
  `--status all` lists active, registered, and locked users on every supported Redmine version. It sends an empty `status=`, which Redmine 4.2 to 5.1 read as "any status", and retries once with `status=*` when Redmine 6.0+ rejects the empty value. A raw `--status '*'` needs Redmine 5.1+; Redmine 4.2 returns no users for it.
</Aside>

```bash
redmine users list --status all
redmine users list --sort created_on:desc --limit 10
# Redmine 5.1+: any status, login contains "smith"
redmine users list --filter 'f[]=status' --filter 'op[status]=*' \
  --filter 'f[]=login' --filter 'op[login]=~' --filter 'v[login][]=smith'
```

A `--filter` key that a dedicated flag also sends (such as `status` or `name`) replaces the flag's value. With `f[]`, Redmine applies only the filters listed in `f[]`; filters set by other flags such as `--status` are dropped.

On Redmine 4.2 to 5.0, `--sort` honours only `login`, `firstname`, `lastname`, `admin`, `created_on`, and `last_login_on`; Redmine 5.1+ can sort by the other user columns too.

## get

```bash
redmine users get <id-or-name> [flags]
```

Aliases: `show`, `view`. Accepts a numeric ID, login, full name, or `me`.

| Flag | Description |
|------|-------------|
| `--include`    | Include related data: `memberships`, `groups`, `auth_source` (repeatable or comma-separated). `groups` requires Redmine 2.1+; `auth_source` requires Redmine 6.0+ and admin privileges. |
| `-o, --output` | Output format |

## me

```bash
redmine users me [flags]
```

Shows the authenticated user's details — useful in scripts to resolve the current account.

| Flag | Description |
|------|-------------|
| `--include`    | Include related data: `memberships`, `groups`, `auth_source` (repeatable or comma-separated). `auth_source` requires Redmine 6.0+ and admin privileges. |
| `-o, --output` | Output format |

With `-o json` (and in the MCP user tools) a user carries these optional keys. They are omitted, not `null`, when Redmine does not send them:

- `passwd_changed_on`, sent by `users get`, `users me` and `users list` but not by `/my/account.json`.
- `twofa_scheme`, only for admins or the user themselves.
- `avatar_url` (Redmine 5.0+), only when the user has an avatar.
- `auth_source` (`id`, `name`) with `--include auth_source` (Redmine 6.0+, admin only).

<Aside type="note" title="users me vs my-account get">
  `users me` hits `/users/current.json` and returns the user record visible to the caller. [`my-account get`](./my_account/) hits `/my/account.json`, which also includes the API key and any custom fields, and is the endpoint paired with the writable self-service `my-account update`.
</Aside>

## create

```bash
redmine users create [flags]
```

| Flag | Description |
|------|-------------|
| `--login`              | Login name — <Badge text="required" variant="danger" /> |
| `--password`           | Password — required unless `--generate-password` is set |
| `--firstname`          | First name — <Badge text="required" variant="danger" /> |
| `--lastname`           | Last name — <Badge text="required" variant="danger" /> |
| `--mail`               | Email address — <Badge text="required" variant="danger" /> |
| `--admin`              | Grant admin privileges |
| `--status`             | Initial status: `1` active (Redmine's default), `2` registered, `3` locked |
| `--language`           | Interface language code such as `en`, `de` or `pt-BR`. Write-only: no API response returns it |
| `--mail-notification`  | Email notification preference: `all`, `selected`, `only_my_events`, `only_assigned`, `only_owner`, `none` |
| `--must-change-passwd` | Force the user to change their password on next login |
| `--generate-password`  | Let the server generate a random password (omit `--password`) |
| `--auth-source-id`     | Numeric authentication source ID for external auth |
| `--send-information`   | Email the account info to the new user |
| `--pref`               | User preference as `key=value` (repeatable). See [preferences](#preferences) |
| `--custom-field` | Custom field value as `name=value` or `id=value` (repeatable; repeat a field for multi-value fields, `name=` clears it). See [custom field values](/commands/issues/#custom-field-values) |

<Aside type="caution" title="Passwords on the command line">
  Passing `--password` on the command line may leak the value to shell history. Prefer `--generate-password` paired with `--send-information`, or set the password afterwards with `users update --password-stdin`.
</Aside>

```bash
# Locked user with a German interface and a hidden email address
redmine users create --login jdoe --firstname Jane --lastname Doe --mail jdoe@example.com \
  --generate-password --status 3 --language de --pref hide_mail=1
```

## update

```bash
redmine users update <id-or-name> [flags]
```

Aliases: `edit`. The user argument accepts a numeric ID, login, full name, or `me`. Only fields whose flags are explicitly set are sent to the server, so partial updates do not clobber other fields.

| Flag | Description |
|------|-------------|
| `--firstname`          | First name |
| `--lastname`           | Last name |
| `--mail`               | Email address |
| `--admin`              | Admin privileges (`--admin=false` revokes them) |
| `--status`             | User status: `1` active, `2` registered, `3` locked |
| `--password-stdin`     | Set a new password read from standard input. In a terminal it prompts twice with hidden input; otherwise it reads stdin and removes one trailing newline. Cannot be combined with `--generate-password` |
| `--generate-password`  | Let the server generate a random password |
| `--must-change-passwd` | Force the user to change their password on next login |
| `--language`           | Interface language code such as `en`, `de` or `pt-BR`; empty for the server default. Write-only: no API response returns it |
| `--group`              | Group name or ID the user belongs to (repeatable). Replaces the user's groups; `--group ""` removes the user from all groups |
| `--mail-notification`  | Email notification preference: `all`, `selected`, `only_my_events`, `only_assigned`, `only_owner`, `none`. `selected` notifies about the `--notified-project` set |
| `--notified-project`   | Project (identifier, name, or ID) to get all notifications for with `--mail-notification selected` (repeatable). Only projects the user is a member of count. Replaces the current set; `""` clears it |
| `--auth-source-id`     | Numeric authentication source ID for external auth |
| `--pref`               | User preference as `key=value` (repeatable). See [preferences](#preferences) |
| `--custom-field`       | Custom field value as `name=value` or `id=value` (repeatable; repeat a field for multi-value fields, `name=` clears it) |

```bash
# Multi-value custom field: repeat the flag
redmine users update jdoe --custom-field Skills=Go --custom-field Skills=SQL

# New password: prompted in a terminal, or piped from a secret store
redmine users update jdoe --password-stdin
pass show redmine/jdoe | redmine users update jdoe --password-stdin

# Two groups, and notifications only for one project
redmine users update jdoe --group Developers --group QA --mail-notification selected --notified-project web
```

<Aside type="note" title="No plain password flag on update">
  `users update` has no `--password` flag, so a new password never ends up in shell history or the process list. The MCP `update_user` tool cannot set passwords at all.
</Aside>

### Preferences

`--pref key=value` sets a user preference. Redmine reads preferences from a `pref` object next to the user attributes and silently ignores keys it does not know, so the CLI only checks the `key=value` form and does not restrict the keys. Repeating a key keeps the last value. Common keys:

| Key | Values |
|-----|--------|
| `hide_mail` | `1` hides the email address from other non-admin users, `0` shows it |
| `time_zone` | A Rails time zone name such as `Berlin`, `UTC` or `Eastern Time (US & Canada)`; empty for the server default |
| `comments_sorting` | `asc` or `desc` (order of the issue history) |
| `no_self_notified` | `1` skips email notifications about the user's own changes, `0` sends them |
| `warn_on_leaving_unsaved` | `1` or `0`: warn before leaving a page with unsaved text |

Other keys depend on the Redmine version, for example `textarea_font`, `recently_used_projects`, `history_default_tab` and `toolbar_language_options`, and from Redmine 5.0 `default_issue_query`, `default_project_query` and `auto_watch_on`. Preferences are write-only: no API response returns them. The same flag works on [`my-account update`](./my_account/).
