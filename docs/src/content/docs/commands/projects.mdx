<Aside type="note" title="Project identifiers">
  Wherever a command or MCP tool takes a project identifier, it must be a Redmine identifier (such as `my-project`) or a numeric ID. Values that could change the request path (empty, `.`, `..`, or anything containing `/`, `\`, `?`, `#`, `%`, or control characters) are rejected with `invalid project identifier` before any request is sent. Commands that also accept a project name (for example `--project` on `issues create`) still resolve names containing those characters by matching against the project list.
</Aside>

## list

```bash
redmine projects list [flags]
```

| Flag | Description |
|------|-------------|
| `--status`     | Status filter: `active`, `closed`, `all`, or a numeric status (`1` active, `5` closed). Default: Redmine lists active projects only |
| `--sort`       | Sort order, e.g. `name` or `created_on:desc` |
| `--filter`     | Raw Redmine filter as `key=value` (repeatable), e.g. `--filter name='~web'`, `--filter created_on='>=2026-01-01'` |
| `--include`    | Extra data, repeatable or comma-separated: `trackers`, `issue_categories`, `enabled_modules`, `time_entry_activities`, `issue_custom_fields` |
| `--limit`      | Maximum number of results |
| `--offset`     | Result offset for pagination |
| `-o, --output` | Output format: `table`, `json` |

The table view always shows `ID, Identifier, Name, Status, Public`. Use `--output json` to inspect any extra sections you requested with `--include`.

<Aside type="caution" title="Closed and archived projects are hidden">
  Since Redmine 4.1 the project list returns **active projects only** unless a status is given, so closed projects are hidden as well as archived ones. Use `--status closed` or `--status all` to see closed projects. Archived projects are never listed by the REST API, not even for administrators, so `--status archived` and `--status 9` are rejected; `--status all` lists active and closed projects.
</Aside>

`--filter` passes Redmine query parameters through unchanged, as on [`issues list`](/commands/issues/#list): plain filters such as `name`, `description`, `created_on` or `updated_on` with Redmine operators, and the generic `f[]`/`op[]`/`v[]` syntax (repeat a key ending in `[]` for several values). A `--filter` key that a dedicated flag also sends (such as `status`) replaces the flag's value. With `f[]`, Redmine applies only the filters listed in `f[]`; filters set by other flags such as `--status` are dropped.

```bash
redmine projects list --status all --sort name
redmine projects list --filter name='~web' --filter created_on='>=2026-01-01'
```

## get

```bash
redmine projects get <identifier> [flags]
```

Aliases: `show`, `view`.

| Flag | Description |
|------|-------------|
| `--include`    | Extra data, repeatable or comma-separated: `trackers`, `issue_categories`, `enabled_modules`, `time_entry_activities`, `issue_custom_fields` |
| `-o, --output` | Output format |

The detail view surfaces homepage, default assignee, default version, enabled modules, and project custom field values whenever they are present on the response.

## create

```bash
redmine projects create [flags]
```

| Flag | Description |
|------|-------------|
| `--name`               | Project name — <Badge text="required" variant="danger" /> |
| `--identifier`         | URL-friendly identifier — <Badge text="required" variant="danger" /> |
| `--description`        | Project description |
| `--description-file`   | Read the description from a file (`-` reads standard input); mutually exclusive with `--description`; an empty or whitespace-only file is rejected |
| `--homepage`           | Project homepage URL |
| `--public`             | Make the project public |
| `--parent`             | Parent project identifier, name, or numeric ID |
| `--inherit-members`    | Inherit members from the parent project |
| `--default-assignee`   | Default assignee for new issues (login, name, or numeric ID) |
| `--default-issue-query` | Public global issue query (name or ID, see [`queries list`](/commands/queries/)) shown as the project's default issue list. <Badge text="Redmine 5.0+" variant="note" /> Older versions ignore it; `projects get` does not show it |
| `--tracker`            | Tracker name or ID to enable (repeatable or comma-separated) |
| `--enable-module`      | Module to enable: `boards`, `calendar`, `documents`, `files`, `gantt`, `issue_tracking`, `news`, `repository`, `time_tracking`, `wiki` |
| `--issue-custom-field` | Issue-level custom field name or ID to enable (repeatable). Names match issue custom fields only |
| `--custom-field`       | Project custom field value as `name=value` or `id=value` (repeatable; repeat a field for multi-value fields, `name=` clears it). See [custom field values](/commands/issues/#custom-field-values). Names match project custom fields only |

```bash
redmine projects create \
  --name "Platform" --identifier platform \
  --homepage https://platform.example.test \
  --tracker Bug,Feature \
  --enable-module issue_tracking,wiki,time_tracking
```

## update

```bash
redmine projects update <identifier> [flags]
```

Every flag is optional; omitted flags leave the corresponding field untouched.

| Flag | Description |
|------|-------------|
| `--name`               | New project name |
| `--description`        | New description |
| `--description-file`   | Read the new description from a file (`-` reads standard input); mutually exclusive with `--description`; an empty or whitespace-only file is rejected (pass `--description ""` to clear the description) |
| `--homepage`           | New homepage URL |
| `--public`             | Set public visibility |
| `--parent`             | New parent (identifier, name, or numeric ID). Pass empty to detach from the current parent. |
| `--inherit-members`    | Toggle inheriting members from the parent project |
| `--default-assignee`   | Default assignee (login, user or group name, or numeric ID; names are matched against the project's members first). Pass empty to attempt to clear (some Redmine versions ignore the clear). |
| `--default-version`    | Default version (name or numeric ID). Pass empty to attempt to clear (some Redmine versions ignore the clear). |
| `--default-issue-query` | Public issue query (name or ID; a query of this project wins over a global one with the same name) shown as the project's default issue list. Pass empty to clear. <Badge text="Redmine 5.0+" variant="note" /> Older versions ignore it; `projects get` does not show it |
| `--tracker`            | Replace the enabled tracker set |
| `--enable-module`      | Replace the enabled module set |
| `--issue-custom-field` | Replace the issue-level custom field set |
| `--custom-field`       | Project custom field value as `name=value` or `id=value` (repeatable; repeat a field for multi-value fields, `name=` clears it). See [custom field values](/commands/issues/#custom-field-values). Names match project custom fields only |

<Aside type="note">
  `--tracker`, `--enable-module`, and `--issue-custom-field` replace the current set when provided. Pass the full desired list, not just additions.
</Aside>

## archive

<Badge text="Redmine 5.0+" variant="note" />
```bash
redmine projects archive <identifier> [flags]
```

| Flag | Description |
|------|-------------|
| `-f, --force` | Skip confirmation prompt |

Archived projects are hidden from the default project listing and cannot be edited until they are unarchived.

## unarchive

<Badge text="Redmine 5.0+" variant="note" />
```bash
redmine projects unarchive <identifier>
```

Restore a previously archived project so it appears in default listings again.

## delete

<Badge text="destructive" variant="caution" />
```bash
redmine projects delete <identifier> [flags]
```

| Flag | Description |
|------|-------------|
| `-f, --force` | Skip confirmation prompt |

<Aside type="caution">
  Deleting a project removes all its issues, time entries, and memberships. There is no undo.
</Aside>

## members

```bash
redmine projects members <identifier> [flags]
```

Lists all members and their roles for a project.
