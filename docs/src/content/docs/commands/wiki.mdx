The `wiki` command (alias `w`) reads and writes pages on a project's wiki.

Every subcommand needs a project. Pass `--project <identifier>`, or rely on the default project of the active profile (see [`auth`](/commands/auth/)).

Page names are sent as a single escaped path segment. An empty name, or one with a `.` or `..` part between `/` or `\` (such as `..` or `a/../b`), is rejected with `invalid wiki page` before any request is sent.

## list

```bash
redmine wiki list [flags]
```

Aliases: `ls`. Lists each page's title, parent page, version, and last-modified timestamp, so you can see the page hierarchy at a glance. JSON output also carries `created_on` and, on Redmine 7.0+, the owning `project`. Results are paginated server-side; combine `--limit 0` with `--offset` to walk large wikis.

| Flag | Description |
|------|-------------|
| `--project`     | Project identifier or numeric ID. Falls back to the default project of the active profile. |
| `--limit`       | Maximum number of results (`0` for all) |
| `--offset`      | Result offset for pagination |
| `-o, --output`  | Output format: `table`, `json` |

## get

```bash
redmine wiki get <page> [flags]
```

Aliases: `show`, `view`. Prints the page metadata and full Textile/Markdown source. Pass `--version` to fetch a historical revision instead of the current one.

Redmine 7.0 added the owning project to the wiki page API response, so `wiki get` shows a `Project` row (and a `project` key in JSON output) against 7.0+ servers. Older servers do not send it and the row is omitted.

| Flag | Description |
|------|-------------|
| `--project`    | Project identifier or numeric ID |
| `--version`    | Page version to fetch (omit or `0` for the latest) |
| `--include`    | Include related data. Only `attachments` is supported. |
| `-o, --output` | Output format |

```bash
redmine wiki get WikiStart --project myproject
redmine wiki get WikiStart --project myproject --version 3
redmine wiki get WikiStart --project myproject --include attachments
```

<Aside>
  Page names with spaces or slashes are URL-escaped automatically, so quote them in your shell: `redmine wiki get "Release Notes/2025-Q4" --project myproject`.
</Aside>

## create

```bash
redmine wiki create <page> [flags]
```

Aliases: `new`. Creates a new wiki page. If a page with the same name already exists, Redmine **overwrites** it. Use [`update`](#update) when you want to be sure you are editing rather than replacing.

| Flag | Description |
|------|-------------|
| `--project`    | Project identifier or numeric ID |
| `-t, --text`   | Page content in Textile/Markdown. <Badge text="required" variant="danger" /> unless `--text-file` is given |
| `-F, --text-file` | Read the page content from a file (`-` reads standard input); mutually exclusive with `--text`; an empty or whitespace-only file is rejected |
| `--title`      | Page title to store the page under instead of `<page>`; Redmine uses it as the URL slug |
| `--parent`     | Title of an existing page in the same wiki to nest the new page under |
| `--comments`   | Change comment recorded in the page history |
| `--attach`     | Path to a file to attach (repeatable) |
| `-o, --output` | Output format |

```bash
redmine wiki create MyPage --project myproject --text "h1. Hello World"

redmine wiki create MyPage --project myproject \
  --text "Content here" --title "My Page" --comments "Initial draft"

# Nest the new page under an existing page
redmine wiki create Installation --project myproject \
  --text "h1. Installation" --parent "User Guide"

redmine wiki create MyPage --project myproject \
  --text "See diagram" --attach ./diagram.png
```

<Aside type="tip">
  Read long content from a file instead of quoting it on the command line: `redmine wiki create Notes --project myproject --text-file notes.md`, or pipe it in with `--text-file -`. The file is sent as read (UTF-8, no trimming; only a leading byte-order mark is dropped).
</Aside>

## update

```bash
redmine wiki update <page> [flags]
```

Aliases: `edit`. Edits an existing page. Only the fields you pass change. When `--text` is omitted, the current page text is fetched and resent unchanged so that retitling or re-commenting does not wipe content.

| Flag | Description |
|------|-------------|
| `--project`        | Project identifier or numeric ID |
| `-t, --text`       | New page content. If omitted, the current text is preserved. |
| `-F, --text-file`  | Read the new page content from a file (`-` reads standard input); mutually exclusive with `--text`; an empty or whitespace-only file is rejected |
| `--title`          | New page title. Renames the page; Redmine keeps a redirect from the old title. Requires the `rename_wiki_pages` permission. |
| `--parent`         | Title of an existing page in the same wiki to move this page under. Pass `--parent ""` to move it to the wiki root. See [parent changes are verified](#parent-changes-are-verified). |
| `--comments`       | Change comment recorded in the page history |
| `--attach`         | Path to a file to attach (repeatable) |
| `--expect-version` | Expected current page version. The server returns `409 Conflict` (and the CLI surfaces error code `conflict`) if the page has moved on since you last fetched it. |
| `--ensure-current` | Refetch the page first and assert its current version on update. Mutually exclusive with `--expect-version`. |
| `--section`        | Section number (1-based) to update. When set, only that section is replaced; the rest of the page remains unchanged. Requires `--text` or `--text-file`. |
| `--section-hash`   | Hash of the original section content, used by Redmine for conflict detection on section edits. Requires `--section`. |

```bash
redmine wiki update MyPage --project myproject --text "Updated content"

redmine wiki update MyPage --project myproject --comments "Fixed typo"

redmine wiki update MyPage --project myproject --title "New Title"

# Move a page under another page, or back to the wiki root
redmine wiki update MyPage --project myproject --parent "User Guide"
redmine wiki update MyPage --project myproject --parent ""

redmine wiki update MyPage --project myproject --attach ./screenshot.png

# Update only section 5 of the page
redmine wiki update MyPage --project myproject \
  --section 5 --text "h3. Updated Section Content"

# Section update with conflict detection
redmine wiki update MyPage --project myproject \
  --section 5 --section-hash abc123 \
  --text "h3. Updated Section Content"

# Optimistic concurrency: fail if the page has been edited since version 7
redmine wiki update MyPage --project myproject \
  --text "Updated content" --expect-version 7

# Convenience: refetch the page first and reuse its current version
redmine wiki update MyPage --project myproject \
  --text "Updated content" --ensure-current
```

<Aside>
  Without `--expect-version` or `--ensure-current`, `wiki update` happily overwrites concurrent edits. Use one of these flags whenever multiple authors might be editing the same page so a stale change fails fast with `code: "conflict"` instead of silently winning the race.
</Aside>

### Parent changes are verified

`--parent` takes a page title the same way page arguments do: spaces may be written as spaces or underscores, and the match is case-insensitive (`"user guide"` finds `User_Guide`). A blank value moves the page to the wiki root. When Redmine applies the parent (new pages, or with the permission below), an unknown parent, the page itself, or one of its own descendants is rejected with `code: "validation_failed"`.

Redmine answers with success even when it **silently ignores** the parent: changing the parent of an existing page requires the `rename_wiki_pages` permission, and without it the field is dropped. So whenever `--parent` is passed to `update` (or to `create` over an existing page), the CLI checks the stored parent. If it did not change, the command fails with exit status `1`:

- the message names the requested and the current parent,
- the details report a `--title` rename that was dropped as well (it needs the same permission) and warn that the other changes in the request (text, comments, attachments) may already have been applied, so do not resend them blindly,
- with `-o json`, this is the standard [error envelope](/guides/output-formats/#json-error-envelope) with code `parent_not_applied`.

New pages always accept a parent, so `create` of a new page needs no extra permission. Updates without `--parent` do not trigger the extra request.

Redmine also follows rename redirects: `--parent Guide` lands under `User_Guide` if `Guide` was renamed to that. The API cannot resolve such a redirect, so in that case `update` succeeds with a warning on stderr instead of an error, and `create` succeeds silently; check the parent with `redmine wiki get`.

When `--text` is omitted, the current text is resent unchanged and pinned to the page version just read, so an edit by someone else in between fails with `code: "conflict"` instead of being overwritten.

```bash
$ redmine wiki update Installation --project myproject --parent "User Guide" -o json
{"error":{"message":"Wiki page \"Installation\": parent was not changed to \"User Guide\"; it is now none (wiki root). Redmine silently ignores parent changes on existing pages unless you have the rename_wiki_pages permission.","code":"parent_not_applied"}}
```

## delete

<Badge text="destructive" variant="caution" />

```bash
redmine wiki delete <page> [flags]
```

Aliases: `rm`. Permanently removes the page along with all its attachments and version history. Child pages are re-parented to the wiki root rather than deleted.

| Flag | Description |
|------|-------------|
| `--project`   | Project identifier or numeric ID |
| `-f, --force` | Skip the confirmation prompt |

```bash
redmine wiki delete MyPage --project myproject
redmine wiki delete MyPage --project myproject --force
```

<Aside type="caution">
  There is no undo. Page history is destroyed in the same call, so make sure you have a copy if you might need the content back.
</Aside>
