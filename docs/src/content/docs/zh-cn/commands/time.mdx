## log

```bash
redmine time log [flags]
```

| 标志 | 描述 |
|------|------|
| `--issue`    | 工单 ID |
| `--project`  | 项目（名称或标识符） |
| `--hours`    | 工时 — <Badge text="必填" variant="danger" /> |
| `--activity` | 活动类型（名称或 ID；项目专用的覆盖活动请使用 `redmine activities list --project <project>` 中的 ID） |
| `--comment`  | 工作描述 |
| `--date`     | 日期（YYYY-MM-DD 或 `today`，默认：今天） |
| `--user`     | 代他人记录工时（`me`、登录名、姓名或 ID） |
| `--custom-field` | 自定义字段值，格式为 `name=value` 或 `id=value`（可重复；多值字段请对同一字段重复使用该标志，`name=` 表示清空）。参见[自定义字段值](/zh-cn/commands/issues/#自定义字段值) |

<Tabs syncKey="time-log">
  <TabItem label="基础">
    ```bash
    redmine time log --issue 123 --hours 1.5 --activity Development --comment "Bug fix"
    ```
  </TabItem>
  <TabItem label="自定义字段">
    ```bash
    redmine time log --issue 123 --hours 2 \
      --custom-field "Billing Code=ACME-42" \
      --custom-field Tags=Onsite --custom-field Tags=Overtime
    ```
  </TabItem>
  <TabItem label="代他人">
    ```bash
    redmine time log --issue 123 --hours 1 --user jsmith --comment "Pair work"
    ```
  </TabItem>
</Tabs>

<Aside type="caution">
  `--user` 需要 Redmine 服务端的管理员权限或“代他人记录工时”权限。同时，目标用户必须是该项目的成员并拥有“记录工时”权限，否则 Redmine 会返回校验错误（`User is invalid`）。
</Aside>

<Aside type="tip" title="必填自定义字段">
  如果服务器定义了必填的工时自定义字段，`time log` 会以 `validation_failed` 失败，直到通过 `--custom-field` 传入这些字段。按名称查找字段需要管理员权限；否则请使用 `redmine time list --limit 1 --jq '.[0].custom_fields'` 得到的数字 ID。
</Aside>

## list

```bash
redmine time list [flags]
```

| 标志 | 描述 |
|------|------|
| `--project`    | 按项目过滤 |
| `--user`       | 按用户过滤：`me`、名称或 ID |
| `--issue`      | 按工单 ID 过滤 |
| `--activity`   | 按活动类型过滤（名称或 ID；项目专用的覆盖活动请使用 `redmine activities list --project <project>` 中的 ID） |
| `--from`       | 开始日期（YYYY-MM-DD 或 `today`） |
| `--to`         | 结束日期（YYYY-MM-DD 或 `today`） |
| `--filter`     | 原始 Redmine 过滤条件，格式为 `key=value`（可重复）。参见[原始过滤条件](#原始过滤条件) |
| `--query`      | 按名称运行已保存的工时查询（与 `--query-id` 互斥） |
| `--query-id`   | 按数字 ID 运行已保存的工时查询 |
| `--sort`       | 排序方式，例如 `spent_on:desc` 或 `hours:desc` |
| `--limit`      | 最大结果数 |
| `--offset`     | 分页偏移量 |
| `-o, --output` | 输出格式 |

<Tabs syncKey="time-list">
  <TabItem label="本周">
    ```bash
    redmine time list --user me --from 2024-01-15 --to 2024-01-19
    ```
  </TabItem>
  <TabItem label="按工单">
    ```bash
    redmine time list --issue 123
    ```
  </TabItem>
  <TabItem label="工时最多优先">
    ```bash
    redmine time list --project myproject --sort hours:desc --limit 10
    ```
  </TabItem>
  <TabItem label="自定义字段">
    ```bash
    redmine time list --project myproject --filter cf_3=Onsite
    ```
  </TabItem>
</Tabs>

### 原始过滤条件

`--filter key=value` 会把 Redmine 查询参数原样传递，与 [`issues list`](/zh-cn/commands/issues/#list) 的逃生通道相同：

- `--filter cf_3=Onsite` — 工时自定义字段 3 等于 "Onsite"（该字段须在 Redmine 中设为可用作过滤条件）
- `--filter spent_on='><2026-01-01|2026-01-31'` — 在日期范围内的工时（`>=`、`<=`、`><` 等 Redmine 运算符均可用）
- `--filter issue.tracker_id=1` — 跟踪器 1 的工单上的工时
- `--filter author_id=me` — 由你创建的工时，包括代他人登记的
- `--filter 'f[]=hours' --filter 'op[hours]=>=' --filter 'v[hours][]=2'` — Redmine 通用的 `f[]`/`op[]`/`v[]` 语法。以 `[]` 结尾的键可重复以发送多个值；使用 `f[]` 时，Redmine 只应用其中列出的过滤条件。

如果 `--filter` 的键与某个专用标志发送的参数相同（例如 `project_id` 或 `user_id`），则以 `--filter` 的值为准。`--from` 和 `--to` 优先于 `spent_on` 过滤条件。

`--query` 在已保存的**工时**查询（`/queries.json?type=TimeEntryQuery`）中按名称解析；[`queries list`](/zh-cn/commands/queries/) 只显示工单查询。

## update

```bash
redmine time update <id> [flags]
```

| 标志 | 描述 |
|------|------|
| `--hours`    | 新工时 |
| `--activity` | 新活动类型（名称或 ID；项目专用的覆盖活动请使用 `redmine activities list --project <project>` 中的 ID） |
| `--comment`  | 新评论 |
| `--date`     | 新日期（YYYY-MM-DD 或 `today`） |
| `--custom-field` | 自定义字段值，格式为 `name=value` 或 `id=value`（可重复；多值字段请对同一字段重复使用该标志，`name=` 表示清空）。参见[自定义字段值](/zh-cn/commands/issues/#自定义字段值) |

## summary

```bash
redmine time summary [flags]
```

按天、项目或活动类型汇总工时记录（`--group-by`，默认 `day`）。与 [`list`](#list) 一样接受 `--project`、`--user`、`--from` 和 `--to`；未指定日期时统计本周。

<Aside type="tip">
  将 `summary` 与 `--from today --user me` 结合使用，可快速查看当天自己的工时分布。
</Aside>
